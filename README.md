# Фінансовий менеджер (Bella mobile)

Особистий фінансовий застосунок у вигляді PWA: бюджет, Net Worth, інвестиції, калькулятор ОВДП, пасивний дохід, цілі, імпорт банківської виписки (Excel / CSV), PIN, синхронізація через Google Drive.

Дизайн і логіка створені в Claude Design. Ця тека містить робочу версію та архів.

## Структура

| Шлях | Що це |
| --- | --- |
| `app/` | **Робочий застосунок.** |
| `app/index.html` | Увесь інтерфейс і логіка (шаблон `<x-dc>` + клас `Component`). |
| `app/support.js` | Рушій Claude Design, що рендерить шаблон через React. Не редагувати вручну. |
| `app/Field.dc.html` | Компонент поля вводу, який підвантажує `index.html`. |
| `app/vendor/` | React 18.3.1 (UMD), локальна копія, щоб застосунок працював офлайн і не залежав від unpkg. |
| `app/_ds/nocturne-…/styles.css` | Токени дизайн-системи Nocturne. |
| `app/sw.js`, `app/manifest.webmanifest`, `app/icon-*.png` | Встановлення як застосунок і офлайн-режим. |
| `android/` | Обгортка Android і скрипт збірки APK. |
| `design/` | Кілька ранніх прототипів і дизайн-система Industry (не публікується). |
| `docs/handoff.md` | Опис екранів, поведінки й стану застосунку. |

## Запуск локально

Службовий воркер працює лише через http, тому файл не можна просто відкрити двічі клацнувши.

```sh
cd app
python3 -m http.server 8000
# відкрити http://localhost:8000
```

## Де користуватись

- **Android:** встановіть APK зі збірки (розділ нижче).
- **Комп'ютер:** локальний сервер із теки `app/`, див. «Запуск локально».
- Публічного сайту немає: дані зберігаються лише на вашому пристрої.

## Як вносити зміни

- Після будь-якої зміни файлів у `app/` збільште версію кешу `C` у `app/sw.js` (наприклад, `fin-v6` → `fin-v7`). Так телефони отримають нову версію.
- Дані користувача зберігаються в `localStorage` під ключем `bella_proto2`. Не перейменовуйте його, інакше збережені дані «зникнуть».
- Сторонні запити: курси НБУ (`bank.gov.ua`), вхід Google і Drive API. Службовий воркер їх не кешує.

## Автоматична збірка APK (Android)

Тека `android/` містить обгортку (WebView), яка показує застосунок з `app/` на телефоні без браузера. Робочий процес `.github/workflows/android.yml` збирає підписаний APK після кожної зміни в `app/` чи `android/` (або вручну: Actions → «Збірка APK» → Run workflow). Готовий файл лежить у кінці запуску, у розділі Artifacts (`fin-manager-apk`).

**Один раз додайте секрети** (Settings → Secrets and variables → Actions → New repository secret):

| Секрет | Значення |
| --- | --- |
| `KEYSTORE_BASE64` | вміст ключа підпису в base64: `base64 -w0 fin-manager-signing-key.jks` (на Mac: `base64 -i fin-manager-signing-key.jks`) |
| `KEYSTORE_PASSWORD` | пароль сховища й ключа |
| `KEY_ALIAS` | `fin` |

Ключ підпису тримайте поза репозиторієм. Нові версії встановлюються поверх старої лише тоді, коли підписані тим самим ключем. Версія береться з номера запуску.

**Вхід через Google в APK (синхронізація Drive).** Сторінку входу Google не можна відкривати у вбудованому вікні, тому APK відкриває її в системному браузері й повертається за посиланням `com.googleusercontent.apps.<ID>:/oauth2redirect`. Потрібен окремий Client ID типу **Android** (Google Cloud → Credentials → Create credentials → OAuth client ID → Android): пакет `ua.fin.manager`, SHA-1 вашого ключа підпису, у Advanced settings увімкнути «custom URI scheme». Цей ID передається збірці змінною `ANDROID_CLIENT_ID` (у GitHub: Settings → Secrets and variables → Actions → **Variables**). Це не секрет, але в репозиторій його не записано. Якщо екран згоди в режимі Testing, вхід доведеться повторювати щотижня: переведіть застосунок у Production (для особистого використання перевірка не потрібна, бо обсяг `drive.appdata` не чутливий).

Локальна збірка (потрібні JDK 17 і Android SDK): `KEYSTORE_FILE=... KEYSTORE_PASSWORD=... KEY_ALIAS=fin ./android/build.sh`.

Обмеження: APK працює на Android 10 і новіше. Дані застосунку окремі від сайту: переносіть через «Копію JSON».

## Звіти й експорт

У «Бюджеті» є «Звіт за період» (3, 6, 12 місяців або весь період): доходи, витрати й баланс по місяцях, норма заощаджень, витрати за категоріями. Кнопка «Експорт у Excel (.xlsx)» (також у «Дані та історія») створює файл із трьома аркушами: «Операції», «По місяцях», «По категоріях». Суми конвертуються у валюту перегляду. У APK файл зберігається в «Завантаження».

## Рахунки, перекази й борги

- **Рахунки.** У Net Worth «Рахунки»: картки й готівка з валютою та початковим залишком. Операція може належати рахунку (вибір у формі, фільтр у Бюджеті, рахунок при імпорті виписки). Перекази між рахунками (з різними валютами теж, із вказаною або розрахованою за курсом сумою) змінюють лише баланси й не потрапляють у Бюджет. Операції без рахунку враховуються як раніше (рядок «Без рахунку»). Видалення рахунку прибирає його перекази й відв'язує операції.
- **Борги й кредити.** «Я винен» зменшує капітал, «Мені винні» збільшує. Платежі зменшують залишок боргу й не створюють операцій у Бюджеті; відсотки не нараховуються. В APK за 7 і 1 день до строку приходить нагадування.
- **APK.** Поле Client ID у налаштуваннях синхронізації приховано: ключ вбудований у збірку.

## Масові дії, правила категорій і копії на Drive

- **Масові дії.** У «Бюджет» → «Історія операцій» кнопка «Вибрати» вмикає вибір: торкніться операцій (або «Усі видимі»), потім змініть категорію або видаліть. Видалення потребує підтвердження, зміни скасовуються в журналі.
- **Правила категорій.** «Правила категорій» у Бюджеті: «якщо опис містить текст, категорія така». Правила мають пріоритет під час імпорту виписки; кнопка «Застосувати до існуючих» змінює або лише операції з категорією «Інше», або всі (крім категорій інвестицій).
- **Копії на Drive.** Після синхронізації застосунок раз на день створює в прихованій теці Drive файл `bella-backup-РРРР-ММ-ДД.json` (зберігаються останні 20). У «Дані та історія» → «Копії на Google Drive» можна переглянути копії, створити нову вручну й відновити дані; перед відновленням поточний стан зберігається окремою копією. Якщо задано пароль шифрування файлу Drive, копії теж шифруються.

## Тести

`npm install && npx playwright install chromium && npm test` запускає `tests/smoke.mjs`: відкриває всі розділи, перевіряє початковий залишок, повторювані операції, навчання категорій в імпорті, шифрування й роботу з Android-мостом (імітація). У GitHub Actions ці перевірки йдуть перед кожною збіркою APK.

## Безпека даних

- **PIN** закриває екран; це не шифрування. Хеш PIN лежить поруч із даними.
- **Шифрування даних на пристрої** («Дані та історія» → Безпека): AES-256-GCM, ключ з пароля (PBKDF2, 150 000 ітерацій). Без пароля дані не прочитати, пароль не відновлюється. Пароль шифрування файлу на Drive тепер зберігається всередині цих даних, а не окремо.
- **Копії JSON не шифруються**, тримайте їх у надійному місці.
- **APK:** розблокування за відбитком чи обличчям замість PIN (лише екран, не ключ шифрування); нагадування за 7 і 1 день до погашення ОВДП і про копію JSON раз на 14 днів (суми в сповіщеннях приховані, якщо ввімкнено PIN або режим «Приховати суми»).

## Що змінено під час упорядкування (жовтень 2026)

**Порядок у проєкті**
- Одна робоча версія в `app/` замість п'яти однакових копій (`new disayn.html`, `app/`, `pwa/`, `design_handoff_finance_app/`, файли в корені).
- Старі прототипи перенесено в `design/archive/`.
- Видалено особисті дані: банківські виписки, скріншоти з банківського застосунку, чати з Claude Design, старі збірки з вашими позиціями. Новий пристрій стартує з порожнього портфеля й без позицій ОВДП (раніше туди були вписані ваші активи).

**Надійність і офлайн**
- React підключено з локальної теки `vendor/` (раніше завантажувався з unpkg при кожному запуску, і без інтернету застосунок міг не відкритися).
- Службовий воркер тепер заздалегідь кешує всі потрібні файли (`support.js`, стилі, React, `Field.dc.html`), тож застосунок відкривається офлайн.
- Службовий воркер більше не кешує відповіді Google Drive (у них ваші фінансові дані) та інших сторонніх сайтів.
- Додано `netlify.toml` із заголовками безпеки (заборона вбудовування в чужі сайти, `nosniff`) і без кешування `index.html` та `sw.js`, щоб оновлення приходили одразу.

**Виправлені помилки**
- Видалення позиції ОВДП зі списку тепер видаляє й пов'язаний актив в Інвестиціях. Раніше актив лишався і далі рахувався в капіталі.
- «Скасувати» в журналі змін тепер повертає й позиції ОВДП, ліміти та цільовий розподіл.
- Блокування PIN після 5 помилок більше не знімається перезавантаженням сторінки.
- «Сьогодні» оновлюється, якщо застосунок відкритий після опівночі. Раніше нова операція отримувала вчорашню дату.
- Для нового пристрою місяць у Бюджеті та дата в формі беруться з поточної дати, а не з жовтня 2026.
- У сторінки з'явилися мова (`lang="uk"`) і заголовок вкладки.

## Перевірено

Автоматично в Chromium (ширина 1280 px і 390 px): усі 9 розділів відкриваються, натиснуто всі не-руйнівні кнопки без помилок JavaScript, додавання операції з телефонного вигляду зберігається, застосунок відкривається без мережі, блокування PIN тримається після перезавантаження.

Не перевірено: синхронізацію з Google Drive (потрібен ваш акаунт), імпорт реальної виписки та вигляд на справжньому телефоні.
